# 03. Архитектура

## 1. Модель данных

### Задача (Task)

| Поле | Тип | Пример | Комментарий |
|---|---|---|---|
| `id` | `string` | `"k3j9x1"` | Уникальный. Генерируется **в оболочке** |
| `title` | `string` | `"Сдать лабу по ФП"` | Уже обрезан от пробелов |
| `done` | `boolean` | `false` | |
| `createdAt` | `number` | `1758050000000` | Метка времени. Тоже приходит **из оболочки** |
| `completedAt` | `number \| null` | `null` | Когда отмечена выполненной |

### Данные (State)

| Поле | Тип | Комментарий |
|---|---|---|
| `tasks` | `Task[]` | Порядок в массиве = порядок посадки = место в саду |

### Вид экрана (View)

| Поле | Тип | Комментарий |
|---|---|---|
| `filter` | `'all' \| 'active' \| 'done'` | Текущий фильтр |
| `query` | `string` | Поиск (не сохраняется в localStorage) |
| `sort` | `'created' \| 'newest' \| 'title' \| 'activeFirst'` | Сортировка |

Всё приложение: `App = { state, view }`. Данные и вид экрана обрабатывают два
отдельных редьюсера: `reducer` и `viewReducer`, а `appReducer` их объединяет
(`core/reducer.js`). Фильтр и поиск влияют только на список; сад всегда показывает все задачи.

> Счётчики, отфильтрованный список, форма деревьев и их места **не хранятся**:
> их вычисляют чистые функции (`filters.js`, `plant.js`). Правило: храним минимум,
> остальное вычисляем. Иначе данные рассинхронизируются.

### Время суток

Не часть состояния приложения, а настройка: `'auto' | 'morning' | 'evening' | 'night'`,
хранится отдельно в `localStorage` (`garden/daytime`).

## 2. Действия (Actions)

Действие — простой объект-описание события. Функций и DOM-элементов в нём нет,
только данные.

| `type` | Остальные поля | Что делает |
|---|---|---|
| `task/add` | `id`, `title`, `createdAt` | Добавляет задачу (сажает росток) |
| `task/toggle` | `id`, `at` | Переключает `done` и выставляет или сбрасывает `completedAt` |
| `task/remove` | `id` | Удаляет задачу |
| `tasks/clearDone` | | Удаляет все выполненные («Собрать урожай») |
| `view/filter` | `filter` | Меняет фильтр |
| `view/query` | `query` | Поиск |
| `view/sort` | `sort` | Сортировка |

### ✅ Ответ на загадку из теории

`id` и `createdAt` вычисляет **оболочка** (`events.js`) в момент клика и кладёт
в action. Редьюсер получает их готовыми, поэтому остаётся чистым:
одинаковый `(state, action)` → всегда одинаковый результат.

## 3. Поток данных (однонаправленный)

```
 ┌──────────┐   DOM-событие   ┌───────────┐   action   ┌────────────────────┐
 │   DOM    │ ──────────────▶ │ events.js │ ─────────▶ │ dispatch (main.js) │
 └──────────┘                 └───────────┘            └─────────┬──────────┘
      ▲                                                          │
      │                                                          ▼
      │                                               appReducer (чистый)
      │                                                          │ новый app
      │                         ┌────────────────────────────────┼─────────────────┐
      │                         ▼                                ▼                 ▼
      │                   render.js (панель)            scene.js (3D-сад)    storage.js
      └───────────────────────  │                                │
                                ▼                                ▼
                    selectors (filters.js)          plantFor, gardenSlot (plant.js)
```

Данные текут **в одну сторону**. `render` и `scene` никогда не меняют состояние,
а `events` никогда не трогает состояние напрямую: только через `dispatch`.

Время суток идёт параллельно: `main.js` читает час → `resolvePhase(choice, hour)` (чистая) →
`renderDaytime` (цвета панели) и `scene.setPhase` (цвета неба и свет).

## 4. Карта чистоты

| Файл | Чистый? | Что можно | Что нельзя |
|---|---|---|---|
| `core/fp.js` | ✅ | Утилиты | Всё внешнее |
| `core/task.js` | ✅ | Создавать новые объекты-задачи | Мутировать аргумент |
| `core/tasks.js` | ✅ | `map` / `filter` / `reduce` | `push` / `splice` / `sort` на аргументе |
| `core/filters.js` | ✅ | Возвращать функции-предикаты, вычислять статистику | |
| `core/reducer.js` | ✅ | Вызывать функции из `tasks.js` | `Date.now()`, генерировать id |
| `core/plant.js` | ✅ | Хеш и псевдослучайные числа из зерна, план сада | `Math.random` |
| `core/daytime.js` | ✅ | Правило «час → время суток», палитры как данные | `new Date()` |
| `shell/render.js` | ❌ | DOM | Менять состояние |
| `shell/scene.js` | ❌ | three.js, WebGL, анимация | Менять состояние |
| `shell/events.js` | ❌ | Слушать DOM, `Date.now()`, генерировать id | Менять состояние напрямую |
| `shell/storage.js` | ❌ | `localStorage`, `JSON`, `try/catch` | |
| `main.js` | ❌ | Хранить текущее приложение в переменной `let`, читать часы | |

> В `main.js` три `let`: текущее приложение, приложение до удаления (для «Вернуть»)
> и выбор времени суток. Это осознанные «точки мутации» на границе мира.
> Переменные переприсваивают, но **сами объекты** состояния никогда не меняют.

## 5. Зависимости между модулями

```
 ЯДРО (чистое)
   fp.js
   task.js     → fp.js
   tasks.js    → fp.js, task.js
   filters.js  → fp.js, task.js, tasks.js
   reducer.js  → task.js, tasks.js, filters.js
   plant.js    → fp.js
   daytime.js  (ни от чего не зависит)

 ОБОЛОЧКА (нечистая)
   render.js   → filters.js
   events.js   → task.js, reducer.js
   storage.js  (ни от чего не зависит)
   scene.js    → plant.js, daytime.js, three.js (vendor/three)
   main.js     → всё выше; scene.js — через динамический import()
```

Если 3D не работает, `import('./shell/scene.js')` падает, а остальное приложение живёт дальше.

Ядро **никогда** не импортирует из оболочки. Если импорт идёт в обратную сторону,
архитектура сломана.

## 6. Рендеринг панели

**Полная перерисовка.** `renderTasks` каждый раз строит HTML списка через
`map(...).join('')` и вставляет его через `innerHTML`.
+ очень просто и очень «функционально»: `view = f(state)`;
− теряется фокус (поэтому `render.js` запоминает его и возвращает);
⚠ пользовательский текст **обязательно экранировать** (XSS!): функция `escapeHtml`.

Анимации появления и удаления карточек делает View Transitions API
(`document.startViewTransition`), если браузер его поддерживает.

**Делегирование событий:** не вешать обработчик на каждую кнопку. Один
обработчик на `<ul>`, а куда кликнули — через `event.target.closest('[data-action]')`.

## 7. 3D-сад

### 7.1. ДНК дерева — случайность без Math.random

```
 task.id ──▶ hashString ──▶ зерно ──▶ randomSequence ──▶ [0.42, 0.07, 0.91, …] ──▶ plantFor
  "a1b2"       FNV-1a       3141…      mulberry32 + scan        числа 0…1           { species, scale,
                                                                                      crown, fruits, … }
```

- `hashString` превращает строку в 32-битное число (хеш FNV-1a через `reduce`).
- `randomSequence(seed, count)` — генератор mulberry32, разложенный на две чистые функции:
  `step` (следующее состояние) и `toUnit` (состояние → число от 0 до 1). Состояния накапливает `scan`.
- `plantFor(id)` описывает дерево **данными**: порода, масштаб, наклон, шары кроны,
  яблоки, ярусы ели, штрихи на берёзе. Из этих чисел `scene.js` собирает 3D-модель.

❓ Почему `Math.random()` здесь не подошёл бы, даже если бы был разрешён в ядре?

### 7.2. План сада — спираль «золотого угла»

```
 gardenSlot(i):  радиус = шаг · √(i + 0.5),  угол = i · 137.5°
```

Каждое новое растение встаёт рядом с предыдущими и не налезает на них,
а сад растёт ровным кругом. `gardenRadius(count)` говорит камере, насколько отодвинуться.
Трава, цветы, камни (`gardenDecor`) и звёзды (`starField`) тоже вычисляются из зерна
и одинаковы при каждом запуске.

### 7.3. Сцена three.js (`shell/scene.js`)

- `sync(tasks)` сравнивает задачи с растениями на сцене по `id`:
  новая задача → росток с анимацией; `done` изменился → росток превращается в дерево
  (или обратно); задачи нет → растение уходит под землю. Растения переезжают на новые
  места, если порядок изменился.
- Детали деревьев — несколько общих форм единичного размера (шар, конус, цилиндр),
  нужный размер задаёт `scale`. Материалы кешируются по цвету.
- Камера облетает сад сама, если её не трогать 4 секунды. Мышь или палец вращают, колесо приближает.
- `setViewShift` сдвигает картинку так, чтобы сад был в свободной от панели части экрана.
- `prefers-reduced-motion`: без облёта, покачивания и анимаций роста.

### 7.4. Время суток (`core/daytime.js`)

| Время | Часы | Небо | Свет | Особенности |
|---|---|---|---|---|
| Утро | 5:00–16:59 | голубое → персиковое | тёплый, высокий | |
| Вечер | 17:00–21:59 | фиолетовое → оранжевое | оранжевый, низкий, длинные тени | немного звёзд, светлячки |
| Ночь | 22:00–4:59 | чёрно-синее | холодный лунный | звёзды, светлячки |

- `phaseOfHour(hour)` — чистое правило. Час приходит аргументом.
- `resolvePhase(choice, hour)`: `'auto'` → по часам, иначе ручной выбор.
- `SCENE_PALETTES` — цвета неба, тумана, земли и света как **данные**. `scene.js` плавно
  смешивает текущую палитру с новой.
- Раз в минуту `main.js` сверяется с часами, так что утро само сменяется вечером.

### 7.5. «Вернуть» после удаления

Это не история действий, а одна ссылка: перед удалением `main.js` запоминает текущий
объект приложения в `appBeforeRemoval`. «Вернуть» просто снова на него ссылается.
Копировать ничего не нужно: старый объект никто не менял (иммутабельность).
