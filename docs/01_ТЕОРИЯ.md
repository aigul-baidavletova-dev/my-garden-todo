# 01. Теория: функциональное программирование в JavaScript

Примеры здесь намеренно **не про задачи**: они про числа, котиков и кофе.
Задача — понять идею и потом самостоятельно перенести её на свой код.

---

## 1. Чистая функция

Функция чистая, если выполняются **оба** условия:

1. **Детерминированность**: одинаковые аргументы всегда дают одинаковый результат.
2. **Нет побочных эффектов**: функция ничего не меняет снаружи (переменные, аргументы,
   DOM, localStorage, консоль, сеть) и ничего снаружи не читает, кроме своих аргументов.

```js
// ❌ Нечистая: читает и меняет внешнюю переменную
let total = 0;
function addToTotal(x) {
  total += x;
  return total;
}
addToTotal(5); // 5
addToTotal(5); // 10 ← те же аргументы, другой результат

// ✅ Чистая
const add = (a, b) => a + b;
add(2, 3); // всегда 5
```

**Скрытые нечистоты**, на которых чаще всего ловят на защите:
- `Date.now()`, `new Date()`: каждый раз разный результат;
- `Math.random()`, `crypto.randomUUID()`: тоже;
- `console.log`: побочный эффект (вывод);
- `document.querySelector(...)`: чтение внешнего мира;
- `arr.push()`, `arr.sort()`, `arr.splice()`, `arr.reverse()`: **мутируют** массив-аргумент.

> 💡 Как тогда создать задачу с id и датой, если `Date.now()` нечистый?
> Подумай: кто может вызвать `Date.now()` *за пределами* чистой функции и передать
> результат *внутрь* аргументом? (Ответ спрятан в `03_АРХИТЕКТУРА.md`.)

**Зачем это нужно:** чистую функцию легко тестировать (вход → выход), её безопасно
переиспользовать, а результат можно предсказать, не запуская программу.

## 2. Иммутабельность (неизменяемость)

Данные после создания не меняются. Нужна «изменённая» версия? Создаём **новую**.

```js
const cat = { name: 'Барсик', age: 3 };

// ❌ Мутация
cat.age = 4;

// ✅ Новый объект; spread-оператор копирует поля
const olderCat = { ...cat, age: 4 };
cat.age;      // 3: оригинал цел
olderCat.age; // 4
```

Массивы:

```js
const nums = [3, 1, 2];

// ❌ мутирующие методы
nums.push(4); nums.sort(); nums.splice(0, 1);

// ✅ немутирующие аналоги (возвращают НОВЫЙ массив)
const withFour  = [...nums, 4];           // вместо push
const sorted    = [...nums].sort();       // копия, потом sort
const sorted2   = nums.toSorted();        // современный метод ES2023
const withoutFirst = nums.slice(1);       // вместо splice
const doubled   = nums.map(n => n * 2);   // вместо цикла с присваиванием
```

**Подвох: spread копирует поверхностно.**

```js
const coffee = { name: 'латте', extras: ['сироп'] };
const copy = { ...coffee };
copy.extras.push('корица');
coffee.extras; // ['сироп', 'корица'] 😱 массив внутри общий!
```

**`Object.freeze`** защищает от случайной мутации (но тоже только верхний уровень):

```js
const frozen = Object.freeze({ a: 1 });
frozen.a = 2;   // молча игнорируется (в 'use strict' / модулях — ошибка TypeError)
```

> Модули (`type="module"`) всегда работают в strict mode, поэтому попытка
> мутировать замороженный объект **упадёт с ошибкой**. Это удобный детектор багов.
> Подумай, как написать `deepFreeze` рекурсивно (задание в `fp.js`).

**Зачем:** если состояние не меняется, можно хранить все старые версии.
На этом построена машина времени.

## 3. Функции первого класса

В JS функция — обычное значение: её можно положить в переменную, в объект,
передать аргументом, вернуть из другой функции.

```js
const greet = name => `Привет, ${name}`;
const actions = { hello: greet };   // функция как значение в объекте
actions.hello('Мир');
```

## 4. Функции высшего порядка (ФВП / HOF)

Функция высшего порядка **принимает** функцию или **возвращает** функцию.

### Встроенные ФВП массивов

```js
const prices = [100, 250, 40, 990];

prices.map(p => p * 0.9);             // преобразовать каждый → [90, 225, 36, 891]
prices.filter(p => p > 100);          // оставить подходящие → [250, 990]
prices.reduce((sum, p) => sum + p, 0);// свернуть в одно значение → 1380
prices.find(p => p > 200);            // первый подходящий → 250
prices.some(p => p > 900);            // хотя бы один? → true
prices.every(p => p > 0);             // все? → true
```

`reduce` — самая мощная: через неё можно выразить и `map`, и `filter`.
Она сворачивает массив во **что угодно**: число, строку, объект.

```js
const words = ['кот', 'кит', 'кот', 'пёс'];
const counts = words.reduce(
  (acc, w) => ({ ...acc, [w]: (acc[w] ?? 0) + 1 }),
  {}
);
// { кот: 2, кит: 1, пёс: 1 }: и никакой мутации acc
```

### Функция, возвращающая функцию (замыкание)

```js
const multiplyBy = factor => n => n * factor;
const triple = multiplyBy(3);  // запомнила factor = 3
triple(5); // 15
```

Это **замыкание**: внутренняя функция «помнит» переменные внешней.
В проекте так удобно делать **фабрики предикатов**: функция получает параметр
и возвращает функцию-условие для `filter`.

### Каррирование

Превращение `f(a, b, c)` в `f(a)(b)(c)`. Позволяет частично применять аргументы.

```js
const between = min => max => x => x >= min && x <= max;
const isTeen = between(13)(19);
[10, 15, 22].filter(isTeen); // [15]
```

## 5. Композиция функций

Большие функции собираются из маленьких, как конструктор.

```js
const trim = s => s.trim();
const lower = s => s.toLowerCase();
const exclaim = s => s + '!';

// без композиции: читается изнутри наружу
exclaim(lower(trim('  ПРИВЕТ ')));

// с pipe: читается слева направо, как конвейер
const shout = pipe(trim, lower, exclaim);
shout('  ПРИВЕТ '); // 'привет!'
```

`pipe(f, g, h)(x)` === `h(g(f(x)))`
`compose(f, g, h)(x)` === `f(g(h(x)))`: то же самое, но справа налево.

> Реализовать `pipe` и `compose` нужно самостоятельно в `src/core/fp.js`.
> Подсказка: это одна строчка с `reduce` (для compose нужен `reduceRight`).

## 6. Декларативность вместо императивности

**Императивно** описываем, *как* сделать; **декларативно**, *что* хотим получить.

```js
// Императивно
const adults = [];
for (let i = 0; i < people.length; i++) {
  if (people[i].age >= 18) adults.push(people[i].name);
}

// Декларативно
const adultNames = people
  .filter(p => p.age >= 18)
  .map(p => p.name);
```

## 7. Редьюсер и действия (actions)

Идея из архитектуры Elm и библиотеки Redux: всё, что происходит в приложении,
описывается **объектом-действием**, а новое состояние вычисляет **чистая** функция.

```js
// действие: просто данные, «что случилось»
const action = { type: 'coffee/addSugar', spoons: 2 };

// редьюсер: (старое состояние, действие) → новое состояние
const coffeeReducer = (state, action) => {
  switch (action.type) {
    case 'coffee/addSugar':
      return { ...state, sugar: state.sugar + action.spoons };
    default:
      return state;  // неизвестное действие: вернуть как есть
  }
};
```

Вместо `switch` можно использовать **объект обработчиков** (lookup table).
Это более «функциональный» вариант: словарь `тип → функция`.
Какой вариант выбрать в проекте, решай сама; на защите стоит объяснить выбор.

## 8. Функциональное ядро, императивная оболочка

Программа без побочных эффектов бесполезна: ей нужно рисовать на экране и сохранять
данные. ФП не запрещает эффекты, а **изолирует** их.

```
       ┌───────────────── оболочка (нечистая) ─────────────────┐
клик → │ events.js → action ─┐                ┌→ render.js → DOM │
       │                     ▼                │                  │
       │        ┌────── ядро (чистое) ──────┐ │                  │
       │        │ reducer(state, action)    │─┘→ storage.js      │
       │        │   → newState              │                    │
       │        └───────────────────────────┘                    │
       └─────────────────────────────────────────────────────────┘
```

Правило проекта: **в `src/core/` нельзя** обращаться к `document`, `window`,
`localStorage`, `Date`, `Math.random`, `console`. Проверить это можно поиском по папке.

## Словарик для защиты

| Термин | Одной фразой |
|---|---|
| Чистая функция | Результат зависит только от аргументов; побочных эффектов нет |
| Побочный эффект | Любое взаимодействие с внешним миром или изменение внешних данных |
| Иммутабельность | Данные не меняются: вместо этого создаются новые версии |
| ФВП | Функция, которая принимает или возвращает функцию |
| Замыкание | Функция, запомнившая переменные окружения, в котором создана |
| Каррирование | `f(a, b)` → `f(a)(b)` |
| Композиция | Сборка функции из функций: выход одной — вход следующей |
| Предикат | Функция, возвращающая `true` / `false` |
| Селектор | Чистая функция, вычисляющая производные данные из состояния |
| Редьюсер | Чистая функция `(state, action) → newState` |
| Ссылочная прозрачность | Вызов функции можно заменить её результатом, и программа не изменится |
