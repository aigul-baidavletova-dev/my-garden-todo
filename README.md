# «Сад» — список задач, где дела вырастают в деревья

Лабораторная работа: применение принципов функционального программирования (ФП)
в веб-приложении на HTML + CSS + JavaScript.

## Главная идея (почему это не «ещё один todo»)

Весь экран — трёхмерный сад. Каждая задача — росток. Выполнила задачу — на её месте
вырастает дерево. У каждой задачи своё уникальное дерево (дуб, ель, яблоня, сакура, берёза),
и оно не меняется после перезагрузки: форма вычисляется **чистой функцией** от id задачи,
без `Math.random`. Небо и свет зависят от времени суток: утро, вечер или ночь.

Вся логика — в чистом ядре (`src/core/`). Библиотека three.js только рисует то,
что ядро описало данными. Это и есть главный аргумент на защите.

## Как запускать

Код разбит на ES-модули (`import` / `export`). Браузер не загружает модули
при открытии файла двойным кликом (`file://`), поэтому нужен локальный сервер:

- VS Code → расширение **Live Server** → ПКМ по `index.html` → *Open with Live Server*
- или в терминале из папки проекта: `npx serve .`

Тесты открываются так же: `tests/index.html`. Или в терминале: `node tests/core.test.js`.

3D-библиотека three.js (лицензия MIT) лежит в `vendor/three/`, интернет для неё не нужен.
В `index.html` её подключает «карта импортов» (`<script type="importmap">`).

## Порядок работы

1. Прочитать `docs/01_ТЕОРИЯ.md`: ФП на примерах, не связанных с задачей.
2. Прочитать `docs/02_КОНЦЕПЦИЯ.md`: идея и стиль «Сад».
3. Прочитать `docs/03_АРХИТЕКТУРА.md`: как данные текут по приложению.
4. Разбирать код по этапам из `docs/04_ПЛАН.md`.
5. Перед сдачей ответить на вопросы из `docs/05_ЗАЩИТА.md`.

В начале большинства файлов короткий комментарий о том, зачем нужен файл.
Вопросы к защите собраны в `docs/05_ЗАЩИТА.md`.

## Карта проекта

```
fp-todo/
├── index.html              разметка (каркас описан комментариями)
├── styles/
│   ├── tokens.css          дизайн-токены: три набора цветов (утро, вечер, ночь)
│   ├── base.css            сброс стилей, типографика, раскладка страницы
│   ├── components.css      холст сада, панель, форма, фильтры, карточки
│   └── animations.css      анимации карточек, reduced-motion
├── src/
│   ├── core/               ЧИСТОЕ ЯДРО: ни DOM, ни localStorage, ни Date.now()
│   │   ├── fp.js           свои утилиты: pipe, compose, curry…
│   │   ├── task.js         операции над ОДНОЙ задачей
│   │   ├── tasks.js        операции над СПИСКОМ задач (map / filter / reduce)
│   │   ├── filters.js      предикаты и селекторы (производные данные)
│   │   ├── reducer.js      (state, action) → newState
│   │   ├── plant.js        «ДНК» дерева и план сада: из id задачи, без Math.random
│   │   └── daytime.js      утро / вечер / ночь: правило и палитры
│   ├── shell/              «ГРЯЗНАЯ» ОБОЛОЧКА: всё, что трогает внешний мир
│   │   ├── render.js       state → DOM
│   │   ├── events.js       события DOM → actions
│   │   ├── storage.js      localStorage
│   │   └── scene.js        3D-сад на three.js
│   └── main.js             точка входа: связывает ядро и оболочку
├── vendor/three/          three.js (MIT), локальная копия
├── tests/
│   ├── index.html          страница с результатами тестов
│   ├── runner.js           мини-фреймворк тестирования (свой!)
│   └── core.test.js        тесты чистых функций
└── docs/                   теория, концепция, архитектура, план, защита
```

## Как готовиться к защите

Код написан целиком. Чтобы уверенно его защищать:
1. Пройти по `docs/04_ПЛАН.md` как по маршруту чтения: этап → файлы → вопросы «Понять».
2. Ответить вслух на `docs/05_ЗАЩИТА.md`.
3. Попросить Claude устроить пробную защиту: вопросы как от преподавателя, без готовых ответов.
